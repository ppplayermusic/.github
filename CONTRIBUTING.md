# Contributing to PPPlayer

Thank you for your interest in contributing to PPPlayer! We welcome contributions of all kinds, whether it's reporting bugs, suggesting new features, improving documentation, or writing code.

## Submitting Issues
When creating an issue, please use the provided templates. Be as detailed as possible to help us understand the problem or feature request. 

- **Bug Reports**: Please include the platform, OS version, app version, reproduction steps, and any relevant logs. Always remove any personal or sensitive information before submitting.
- **Feature Requests**: Focus on the problem you're trying to solve and how you'd expect the feature to work.

## Development Workflow

### Flutter & Local Setup
If you are contributing to the main `ppplayer` Flutter application, please refer to the specific setup instructions in the app's repository [README](https://github.com/ppplayermusic/ppplayer#readme). We keep setup instructions localized to each project so they don't apply incorrectly to other repositories (like the website).

### Making Changes
- Check out the existing documentation and past issues to understand the project's current state.
- Create a feature branch for your work. Keep branches scoped to a specific issue or feature.
- Follow existing code style and conventions you see in the repository. (We primarily use standard Dart formatting for the app).

### Pull Requests
1. Ensure your code builds correctly and resolves the issue it aims to fix.
2. Submit your PR and fill out the provided Pull Request template.
3. If a section of the checklist (like tests or documentation updates) does not apply to your change, you may mark it as "N/A" (Not Applicable).
4. Wait for maintainers to review your PR. We may request some changes before merging.

Thank you for contributing!
